# Comparison Assets

Read `brief.md`, `research/research.md`, `research/claims.json`, and `knowledge/seobility/citation-policy.md`. Read [references/asset-policy.md](references/asset-policy.md) before collecting third-party or user-authored material.

Prepare only visuals that have a clear job in the brief. Prefer current official product screenshots that demonstrate a decision-relevant workflow or feature. Do not use generated interface images as evidence.

Standing user direction (30 August 2026): include relevant public official-page screenshots without a separate manual screenshot-approval step. Perform the source, context, privacy, legibility and attribution checks in the asset policy yourself. An absent explicit reuse license alone is not a reason to silently deliver image-free articles. Record the actual use basis honestly; user editorial authorization is not vendor permission. Publication authorization and the stopped article-production queue remain separate boundaries.

For each planned asset:

1. Confirm the source is public, current, and relevant to a supported claim or documented review theme.
2. Capture enough context to avoid misrepresentation. Crop only for focus or privacy and record the change.
3. Save a local file under `assets/` when use is appropriate; never hotlink.
4. Record asset ID, filename, purpose, source URL, capture date, claim or section mapping, caption, alt text, publication attribution, reference or footnote mapping when needed, edits, and use notes in `assets/manifest.md`.
5. If the asset cannot be used safely, mark it unavailable and provide a text fallback.

Pass the handoff only when every required brief asset is ready or has an approved fallback and every usable asset has publication-ready caption and attribution text. Optional missing assets do not block writing.
